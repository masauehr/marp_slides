# Claude Codeでの開発スタイル ― 作業フォルダを軸にした開発サイクル

2026-08-19、`2026-09-18-vibe-coding.md` スライド21のポンチ絵（`images/dev_cycle.svg`）を作り直す過程で言語化した、Claude Codeでの開発スタイルのまとめ。

## 全体像：4段階の循環サイクル

作業フォルダ（コード・マニュアル・ルールを蓄積する場所）を中心に、以下の4工程が双方向に情報をやり取りしながら循環する。

```
        ①自然言語でコード生成
              ↕
④アプリ高度化 ⇄ 作業フォルダ ⇄ ②毎回マニュアル化
バグ修正          ↕
        ③スケジュール実行を日々確認
```

### ① 自然言語でコード生成
- コードを一行も書かず、自然言語の指示だけで試作品を高速に作る
- コード知識は不要。バイブコーディングらしさが最も出る工程

### ② 毎回マニュアル化
- チャットでのやり取り（バグ取り・機能追加・Q&A）を、その都度AIに指示してマークダウンのマニュアルにまとめさせる
- 人手だと面倒で続かないが、AIになら気兼ねなく「まとめて」と指示できるので、毎回続けられる
- CLAUDE.mdや手順書として作業フォルダに蓄積されていく

### ③ スケジュール実行を日々確認（GitHubへ自動push・何でも自動化）
- 完成したコードをGitHubへ自動pushし、定時実行などで「何でも自動化」する
- 自動化されたデータ取得・グラフ化・検証結果を、人がスマホを持って日々確認する
- 確認の中から「新しいアイデア」や「バグ発見」が生まれる

### ④ アプリ高度化・バグ修正
- ③で見つけたアイデアやバグをもとに、作業フォルダを読み込んで続きから開発を再開する
- ここで①（自然言語でコード生成）に戻り、サイクルが続く

## なぜ毎回プロンプトを入力し直さなくていいのか

コード・マニュアル・セキュリティ等のルールを作業フォルダに置いておくと、次回の作業継続時にAIがその中身を自動で読み込む。そのため、経緯や制約を毎回説明し直す必要がなく、「続きから」と言うだけで文脈を保ったまま開発を再開できる。これが④→①のつながりの本質。

## GitHubで閲覧するもの

GitHubにpush・公開するのは、エージェントが自動化処理した成果物そのもの。具体的にはWebアプリ、記事（マニュアル・ドキュメント）、自動化処理の結果のグラフや検証結果など。「コードを公開する」というより「自動化の成果を見える化する」という位置づけ。

## バイブコーディングとしての強み

- 試作品の高速開発（プロトタイピング）に向いている。まず作って、使いながら完成させていくスタイル
- コードの知識がなくても、自然言語で指示するだけで形にできる
- 「動くもの」を作りながら学べるので、学習と開発が同時に進む
